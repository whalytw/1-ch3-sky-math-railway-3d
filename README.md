# 天空函數鐵道 3D — 噴射競速 V1.1

2026-10-24 更新。完整版本，可直接覆蓋原專案；原 V1.0／V0.3 的 `math.js` 題庫完整保留。

## 使用方式

解壓縮後，將資料夾內全部檔案上傳或覆蓋原 GitHub Pages 專案。請連同整個 `src/` 一起更新，尤其包含新增的 `scene-worker.js` 與 `effects.js`，不要只換 index.html。上傳後按 Ctrl+F5，確認頁首為「三人競速 V1.1」。

本機測試：在本資料夾執行 `python -m http.server 8000`（Windows 亦可用 `py -m http.server 8000`），以 Chrome／Edge 開啟 `http://localhost:8000`。請透過 HTTP 伺服器或 GitHub Pages 開啟，直接雙擊 index.html 可能被瀏覽器限制。

不需安裝 npm 執行套件、下載大型 3D 引擎、模型、音效或使用外部 CDN。

## 這次的九項改版

1. **流暢轉彎**：以連續曲線與連續切線取代逐段更新鏡頭方向；加入時間一致的朝向平滑，移除預設 30 FPS 限制。地形在背景 Worker 產生，前方路段預載，場景緩衝與 VAO 重複使用；自動畫質以約 60 FPS 為目標調整解析度。
2. **速度感**：重新調整世界與車輛比例，60 km/h 的場景位移約為 V1.0 的 6.25 倍；比賽距離、速度與時間仍依實際公尺與 km/h 計算。枕木與近景更密集，噴射時視角略為拉寬，並加入漫畫放射速度線。
3. **衝線滑行**：GOAL 後軌道繼續延伸 600 公尺。正式完賽時間與名次在通過 5,000 公尺當下固定；鏡頭用 2 秒轉到主角正面，主角微笑、揮手，礦車從衝線當時速度用 15 秒線性減速至 0。滑行期間停止出題與噴射加速。
4. **起終點人群**：兩面可辨識的 START／GOAL 立體字樣、拱門、起點與終點歡呼觀眾。起跑先以較寬鏡頭呈現起點，再平順收進追隨鏡頭。
5. **彈出噴射引擎**：左右各一具引擎；啟動時依 0%→110%→90%→105%→100% 彈出。加速耗盡後縮小收起；尚未降回 60 時再獲得加速，會重新彈出。
6. **三級噴射**：每次答對的秒數形成一段排程；待用段數立即決定 Level，最高 Level 3。不同級別有更長、更寬的火焰與更強速度線。
7. **自己的解題紀錄**：完賽按鈕只開啟該玩家區域的紀錄，可在區內捲動、展開詳解與圖形。這個面板不開全域對話框、不暫停另外兩區；其他學生仍可答題與加速。
8. **完整跳躍角色**：補齊髖部、大腿、小腿、靴子與空中站姿；從後方超越其他玩家（包含第三名超越第二名）時會跳起轉圈。
9. **遮擋輪廓**：當隔壁軌道、山坡或其他物件遮住自己的礦車與主角時，用自己的隊伍色顯示透視外框。WebGL2 採深度與 stencil 判定，保留輪廓而不把整個遮擋物塗成角色色。

## 新加速規則

| 狀態 | 上限速度 | 速度變化 |
|---|---:|---|
| 無加速段 | 60 km/h | 每秒減少 5 km/h，最低回到 60 |
| Level 1：1 段尚未用完 | 75 km/h | 由當時速度在 1.5 秒內升至上限 |
| Level 2：2 段尚未用完 | 90 km/h | 升級後 1.5 秒內升至上限 |
| Level 3：3 段以上尚未用完 | 100 km/h | 升級後 1.5 秒內升至上限 |

降級時若當前速度高於新級別上限，依每秒 5 km/h 逐漸下降，不瞬間跳速。加速耗盡但速度尚未降回 60 時又答對，引擎會再次彈出；若當時速度已高於新上限，同樣依每秒 5 km/h 降至該上限。

起步仍保留原本 0→60 km/h 的 5 秒加速；衝線前、起步完成後，速度不會低於 60。衝線後則依 15 秒停車規則減至 0。

### 依本次指定的例子

| 遊戲時間 | 內部排程 | 當下引擎 |
|---|---|---|
| 25.1 秒答對，獲得 10 秒 | 第一段：25.1～35.1 | 立即 Level 1；26.6 秒達 75 km/h |
| 30.1 秒又答對，獲得 20 秒 | 第二段接在後面：35.1～55.1 | 第一段尚未用完，立即 Level 2；31.6 秒達 90 km/h |
| 35.1 秒 | 第一段耗盡，只剩第二段 | 降至 Level 1，速度從 90 以每秒 5 km/h 降回 75 |
| 55.1 秒 | 第二段耗盡 | 引擎收起，速度以每秒 5 km/h 降回 60 |

遊戲畫面只顯示目前 Level 與總剩餘加速秒數，不顯示這些內部排程時間。每次獲得的段落與時間保存在該場內部紀錄中。

## 原本保留的規則

- 三人統一教師設定，三秒倒數後一起發車，GO 開始計時。
- 同一張隨機地圖，三條軌道實際弧長各 5 公里；前後半段各 2.5 公里，共用兩種不同主題風景。
- 風景共八種：森林、丘陵、雪地、火山、田園、沙漠、鄉下、湖畔。
- 各區自己的大亮點與百分比、另外兩車的小亮點、碼表、速度、加速秒數。
- GO 後 8 秒出第一題；作答時持續行車。答對、答錯、逾時都固定等待 5 秒出下一題。
- 每題一張求救卡，立即扣 10 秒，最低扣到 0；扣到 0 就立即逾時。
- 題目使用黑底半透明卡片，數字鍵盤在右下，角色保留在左下。長題可在卡片內捲動。
- 數字鍵按下立即輸入；± 切正負、⌫ 刪除、→ 換欄、✓ 送出。選擇題先選再確認。
- 三人全數完賽且滑行停妥後，開始下一組。各玩家的正式碼表在自己衝線當下停止。
- 教師設定、玩法與切換背景分頁仍會全場暫停；自己的解題紀錄不會。

## 題庫、成績與觸控

原題庫涵蓋對稱／中點、函數值、直線斜率截距、拋物線平移、配方、判別式、二次函數極值、營收與面積最佳化。預設前四類、每題 45 秒，可選 10～180 秒或依題型預設計時。啟用題型按順序輪替，直到各自完賽。

設定與完賽紀錄保存在同一瀏覽器 localStorage，最多 200 場，可在統一設定匯出 CSV；不同電腦不自動同步。比賽中更改難度及秒數影響下一場；音效與畫質即時生效。

三人輸入維持 Pointer Events、依 pointerId 獨立處理、後續 click 去重、不以 isPrimary 排除其他學生。數字鍵至少 44 CSS 像素，不在每次輸入時重建鍵盤。統一設定保留觸控接收計數，可比較三人同按與 AirSync／有線觸控回傳的差異。

## 效能與驗證範圍

以 Surface Pro 8 的輕量低多邊形場景為目標：單一 WebGL2 context、三個 viewport、共用 GPU 緩衝、快取頂點狀態、背景地形產生、距離裁切、預載與快取淘汰。沒有大型貼圖、即時陰影、全畫面動態模糊或外部 3D 引擎。預設目標約 60 FPS；若仍不順，可選省電畫質。

已完成：

- 原題庫 7,200 題及常數 ±1 顯示回歸。
- 指定的 25.1／30.1 秒排程例子、三級上限、1.5 秒加速、5 km/h/s 消退、引擎彈出各階段、再次點火與完整比賽。
- 15 秒衝線滑行、跨線時間固定、滑行距離、600 公尺延伸與兩秒正面運鏡。
- 20 種地圖種子、3,060 組路線／鏡頭取樣、連續轉向、角色完整下半身與構圖。
- 三個重疊觸點、非主要觸點、快速交錯按鍵、長按、取消與 click 去重。
- 實際 JavaScript 渲染器的 60 Hz 更新與 stencil 狀態檢查、背景 Worker 訊息／幾何傳送。
- 實際 OpenGL ES 3 著色器、模型與遮擋外框的離屏渲染檢查。
- 瀏覽器內自己的紀錄面板，以及紀錄開啟時其他兩區能繼續倒數、作答、加速。

可用 `npm test` 重跑隨附的 Node.js 測試，不需安裝套件。

測試瀏覽器未提供 WebGL2，瀏覽器操作使用 2D 相容模式；3D 模型另用 OpenGL ES 3 離屏驗證。2D 相容模式的造型與特效較簡化。尚未在真正的 Surface Pro 8／IFP8653／AirSync 連線上測得實際幀率與多點觸控表現，因此不保證任何環境固定達到 60 FPS。網頁也無法補回硬體或 Touchback 未傳入瀏覽器的觸點。
